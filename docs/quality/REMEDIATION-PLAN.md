# 知行智学（zx-learn）质量整改计划

> 依据：[QUALITY-SUMMARY.md](./QUALITY-SUMMARY.md)、[RELEASE-GATE.md](./RELEASE-GATE.md)、[DEFECTS.md](./DEFECTS.md)
> 编制日期：2026-11-16
> 范围：只覆盖总结报告中已登记的风险与未关闭门禁项；不新增功能、不做架构重构。
> 时间口径：本计划只排优先级与依赖顺序，不承诺工期。
> 跨仓库说明：CodeJudge 复用本仓库底座，但两套环境、密钥、数据彼此独立；**不得把 CodeJudge 的整改结果或压测数字直接填入本仓库证据**。

## 1. 整改原则

| 原则 | 说明 |
|---|---|
| 先生产化、后优化 | 密钥、迁移、入口安全未关闭前，不投入性能优化 |
| 一项一验收 | 每项必须有命令与可观察结果；不接受“代码已改”作为完成 |
| 证据可追溯 | 完成后回填 `RELEASE-GATE.md` 对应行，并保留脱敏输出 |
| 不做范围外工程 | 不引入 K8s、多活、全链路追踪；容量先如实声明边界 |

**优先级定义**

- **P0（发布阻断）**：不完成不得开放公网或不得上线。
- **P1（受控内测前）**：影响内测可信度或可能造成资金/数据损失。
- **P2（发布后迭代）**：不阻断发布，但需排期关闭。

## 3. P0 整改项（发布阻断）

### M1 · 生产密钥与配置替换

**对应**：R1、门禁 B1–B6

**动作**
1. 生成并注入：JWT 签名密钥（≥ 32 字节）、支付回调 `PAY_CALLBACK_SECRET`、MySQL / Redis / RocketMQ / PostgreSQL 口令。禁止沿用 `.env` 模板中的任何开发值。
2. 密钥只进入目标环境的环境变量或密钥管理，不入库；复核 `.env` 仍被忽略。
3. 收敛 CORS 与网关白名单到生产域名与端点；删除调试用开放规则。
4. 在验收环境用旧密钥签发的 token 做一次反向验证，确认全部 401。
5. 复跑上线审查脚本与支付回调验签用例。

**验收标准**
- `scripts/verify-go-live-audit.sh` 全部通过，B 组检查点无 FAIL。
- 16 个服务全部正常启动，无“默认口令/占位值”告警。
- 支付回调：正确签名通过；错误签名与未配置密钥被拒（fail-closed）。
- CORS 仅放行生产前端域名，跨域预检不再返回通配。

**证据回填**：`RELEASE-GATE.md` B1–B4、B6 → PASS；`docs/GO-LIVE-CHECKLIST.md` B 组勾选。

**依赖**：无。必须先于 M2、M6 完成。

### M2 · 迁移与备份在生产执行

**对应**：R4、门禁 C1–C2

**动作**
1. 迁移前完成可校验的备份（记录校验和与恢复命令），并在隔离库做一次恢复演练。
2. 在生产按顺序执行 9 个迁移脚本，逐段检查 `[OK]`；遇到失败立即停止并按回滚方案恢复，不允许“跳过继续”。
3. 执行后跑 `sql/reconcile.sql` 的 8 个断言项，确认命中 0 行；观察项单独查看，不当作失败。
4. 复核课程 13 门、目录 78 行、孤儿目录 0、`cover_url` 长度 512。
5. 记录执行前后行数与关键业务数据抽样（脱敏）。

**验收标准**
- 9 个脚本一次执行全部 `[OK]`；重复执行不报错（幂等已在空库验证）。
- 8 个对账断言命中 0 行。
- 恢复演练可还原到备份时点，行数一致。
- 迁移记录归档为脱敏输出，不含连接串与口令。

**证据回填**：`RELEASE-GATE.md` C1–C2 → PASS；`docs/GO-LIVE-CHECKLIST.md` C 组勾选。

**依赖**：M1（数据库口令更换后执行，避免两次改密）。

### M3 · 收敛教师注册入口

**对应**：R3、门禁 A6

**动作（二选一，必须书面决策）**
- **方案 A（关闭自助注册）**：`/teachers/register` 仅允许管理员或内部调用；匿名与学员调用返回 403/404；教师由管理员创建或导入。
- **方案 B（审核制）**：保留提交入口，但新账号状态为“待审核”，不可登录、不可发布课程；管理员审核通过后才生效。

无论选哪种：
1. 更新权限矩阵与接口文档，明确谁可以创建教师。
2. 在安全回归脚本中新增“匿名注册被拒 / 待审核不可登录”断言。
3. 清理历史上自助注册产生的无效教师账号（仅清理确认无业务数据的账号）。

**验收标准**
- 匿名调用注册接口不再产生可用教师账号。
- 方案 B 下待审核账号登录返回明确业务码，不返回 500。
- 安全回归新增断言通过，原 13 类垂直越权用例不回归。

**证据回填**：`RELEASE-GATE.md` A6 备注新增“注册入口已收敛”；`DEFECTS.md` §7 移除“教师自助注册”条目。

**依赖**：M1（管理员账号口令已更换）。

---

### M4 · 恢复 RAG 向量化能力

**对应**：R2

**动作**
1. 确认 embedding 资源可用性：充值额度或切换供应商；配置项只放在环境变量中。
2. 增加启动自检与调用失败告警：余额不足/鉴权失败时明确报错，不再静默降级为“无知识库”。
3. 跑通一条完整链路：上传文档 → 切分 → 向量化 → 入库 → 检索命中。
4. 在页面对“知识库不可用”给出明确状态，不展示空结果冒充“无匹配”。
5. 若首发确定不含 AI 助教：隐藏入口并在发布说明中声明，不得保留可点击但必失败的入口。

**验收标准**
- 单文档入库后分片数 > 0，检索能返回预期片段。
- 断网/欠费场景返回明确业务错误，前端有提示。
- 评测脚本或回归脚本包含一次入库 + 检索。

**证据回填**：`RELEASE-GATE.md` §6 移除 RAG 边界；`TEST-REPORT.md` §7 风险 3 关闭；`docs/GO-LIVE-AUDIT-2026-09-16.md` 追加复验结论（不覆盖原记录）。

**依赖**：M1（供应商密钥更新）。

---

### M5 · 建立最小可观测性

**对应**：R5、门禁 E1–E4

**动作**
1. 死信告警：对 `order_msg` 死信数量建规则，> 0 即告警；验证重放任务可消费。
2. 日志集中：至少做到容器日志有大小上限与轮转，关键错误可按 traceId 检索。
3. 健康检查：逐个服务核验 health/info/metrics 端点，纳入探活与发布后检查表。
4. 上线观察项固化为清单：错误率、P95、GC、连接池、死信数、队列积压，观察窗不少于 15 分钟。
5. 触发一次“毒消息 → 死信 → 告警 → 重放”的演练。

**验收标准**
- 毒消息演练中，告警在 90 秒内可见，重放后业务数据恢复一致。
- 任一服务不可用时，探活能发现，不依赖人工登录服务器。
- 日志磁盘占用有上界，不会无限增长。

**证据回填**：`RELEASE-GATE.md` E1–E4 → PASS；`DEFECTS.md` §7 移除“死信仅日志 warn”。

**依赖**：M1、M2（告警需要稳定环境与真实数据）。

---

### M6 · 启用 HTTPS 与入口收敛

**对应**：R6、门禁 D5–D7

**动作**
1. 配置证书与 80→443 跳转，启用 HSTS；证书私钥不入库。
2. 仅网关卡口对外，其余服务与中间件不发布公网端口；逐项核对编排与安全组。
3. SSE 与 WebSocket 路径关闭代理缓冲、放宽超时；支付回调地址改为 HTTPS。
4. 前端 API 基址改为同源 HTTPS，消除混合内容。
5. 复跑 API 矩阵与前端断言，重点验证登录、课程详情、支付回调、AI 助教流式输出。

**验收标准**
- HTTP 全部跳转 HTTPS；浏览器无混合内容告警。
- SSE 首包与逐字输出正常，不出现整段延迟。
- 738 次接口探测仍为 0 个 5xx；前端 56/56 通过。

**证据回填**：`RELEASE-GATE.md` D5–D7 → PASS；`TEST-REPORT.md` §2 环境说明更新。

**依赖**：M1、M5。

## 4. P1 整改项（受控内测前）

### M7 · 支付单落库与幂等校验

**动作**
1. 新建支付单表：订单号唯一索引、状态、金额、回调原文摘要、创建/更新时间。
2. 查询与回调改为读库；回调重复投递按“订单号 + 状态机”幂等处理。
3. 增加对账：支付成功但未开课的订单必须可查询；与 `order_msg` 重放联动。
4. 保留内存缓存作为加速层，但不再是唯一数据源。

**验收标准**
- 服务重启后支付单可查，不丢失。
- 同一回调重复投递 3 次，只产生一次状态迁移与一次开课。
- 新增断言并入 `verify-purchase-guard` 或独立脚本，失败即阻断。

**证据回填**：`DEFECTS.md` §7 支付单条目改为已修复；`RELEASE-GATE.md` A4 备注。

### M8 · 双机压测与慢查询基线

**动作**
1. 在独立压测机复跑核心接口、秒杀与 SSE 场景，记录机器配置与网络拓扑。
2. 开启慢查询日志，采集 Top 10 慢 SQL，给出索引或改写方案；至少处理影响核心链路的 3 条。
3. 给出“下界 / 参考值 / 保守容量”三档结论，明确哪些数字可对外。

**验收标准**
- 两机结果与差异原因写入 `docs/PERF.md`。
- Top 10 慢 SQL 均有结论（已优化 / 可接受 / 待排期）。
- 对外材料只使用标注为“参考值/保守容量”的数字。

**证据回填**：`QUALITY-SUMMARY.md` §3/§6 更新；`RELEASE-GATE.md` 已知边界移除“无慢查询回归”。

### M9 · JWT 双钥轮换

**动作**
1. 签发 token 带 `kid`；服务端同时持有当前密钥与上一把密钥，按 `kid` 验签。
2. 轮换流程：先加入新密钥并双钥并行 → 新签发使用新密钥 → 旧 token 自然过期后移除旧密钥。
3. 写清回滚步骤：旧密钥未移除前可随时回退。

**验收标准**
- 轮换过程中在线用户不被强制登出；新旧 token 均可验签。
- 旧密钥移除后，旧 token 按预期 401。
- 流程写入 `docs/GO-LIVE-CHECKLIST.md` F 组并演练一次。

**证据回填**：`RELEASE-GATE.md` §6 移除“JWT 无双钥过渡”。

## 5. P2 整改项（发布后迭代）

### M10 · 前端验证纳入 CI

**动作**：在 CI 增加 `npm ci`、类型检查、前端断言与 `vite build`，失败即阻断；保留现有后端 JaCoCo 步骤。先跑通一次基线，再设为必过。

**验收标准**：故意制造一个类型错误时 CI 失败；正常提交全绿。

### M11 · 手机号脱敏

**动作**：运营后台列表与详情默认掩码展示，查看完整号码需二次授权并记录审计日志。

**验收标准**：默认接口不返回完整手机号；越权获取完整号码被拒；审计日志可查。

## 6. 执行顺序与依赖

```text
M1 密钥 ──┬─→ M2 迁移/备份 ──→ M5 可观测性 ──→ M6 HTTPS ──→ 受控内测
          ├─→ M3 教师注册
          ├─→ M4 RAG
          └─→ M9 JWT 双钥（可与 M2 并行）

M7 支付落库（P1，与 M2 并行，依赖数据库迁移窗口）
M8 双机压测 + 慢查询（P1，M6 后执行）
M10 前端 CI、M11 脱敏（P2，发布后）
```

**关键路径**：M1 → M2 → M5 → M6。M3、M4 可与 M2 并行，但必须在上线前关闭。M7 若与 M2 同窗口执行，需把建表脚本并入迁移序列并重新跑幂等验证。

## 7. 验收与回填规则

1. 每项完成后在 `RELEASE-GATE.md` 填写日期、命令、脱敏输出摘要、执行角色。
2. 只有复验命令真实通过才可把结论改为 PASS；不得先改文档后补验证。
3. 新增断言必须进入脚本并入库，不能只保留终端记录。
4. 整改中发现新缺陷，按 `DEFECTS.md` 的 P0–P3 口径登记。
5. 全部 P0 完成后，重新生成 `QUALITY-SUMMARY.md` 的总体结论。

## 8. 完成定义（DoD）

| 阶段 | 完成条件 |
|---|---|
| 可受控内测 | M1–M6 全部 PASS；B/C/D/E 组无 ❌ 阻断 |
| 可公开发布 | 受控内测条件 + M7、M8、M9 完成；已知限制中不再含资金与权限风险 |
| 质量体系稳定 | M10、M11 完成；CI 可拦截前端回归；敏感数据默认脱敏 |

## 9. 明确不做

- 不引入 Kubernetes、多活、Service Mesh。
- 不为“AI 可用”而用假数据或空结果填充知识库。
- 不把同机压测数字包装成生产容量承诺。
- 不因整改而放宽既有 9 条不变量与 8 个对账断言。
