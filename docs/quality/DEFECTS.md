## 2. QA 阶段缺陷（BUG-001~011）

| 编号 | 级别 | 现象 | 根因 | 修复 | 验证 |
|---|---|---|---|---|---|
| BUG-001 | P0 | 任意登录学员可自建角色并绑定管理端菜单，形成提权链 | 角色/菜单/权限点 Controller 类级无 `@RequireRole`；拦截器只在有注解时生效，无注解即默认放行 | 三个 Controller 加类级 `@RequireRole(STAFF)` | 6 条越权断言由成功转为 403；管理员对照组 200（§5 BUG-001） |
| BUG-002 | P1 | RAG 知识库上传/检索经网关 404 | `learning-service` 的 `/admin/**` 通配路由排在 aigc 之前，抢走 `/admin/knowledge/**` | 收窄 learning 路由，aigc 路由补 `/admin/knowledge/**` | 3 个端点由异常转为正常可达，异常数 3 → 0（§5 BUG-002） |
| BUG-003 | P1 | 任意登录用户可写入/删除向量库；`search/all` 全表扫描；非数字 id 返回 500 | 写接口无角色注解；topK 直接传 `Integer.MAX_VALUE`；`Long.parseLong` 未捕获异常 | 补角色校验、topK 上限、id 解析兜底 | 对应断言通过（§5 BUG-003） |
| BUG-004 | P1 | 凭 sessionId 可读取/删除/改他人 AI 会话 | 会话接口只校验登录，不校验归属 | 增加会话归属校验 | 水平越权用例由成功转为拒绝（§5 BUG-004） |
| BUG-005 | P1 | 管理端“草稿”标签页筛选恒为空 | 网关白名单路径短路放行且从不注入 `user-info`，服务端拿不到身份 | 白名单改为可选鉴权并注入身份 | 管理员对照组断言由 0 转 1（§4 BUG-005） |
| BUG-006 | P2 | 匿名可传 `status=0` 枚举未上架/草稿课程 | 课程列表把 `status` 原样透传 | 匿名强制 `status=1`，登录按身份放行 | 匿名/登录对照组断言通过（§5 BUG-006） |
| BUG-007 | P2 | 支付单内存表只增不减，长跑必然 OOM | `ConcurrentHashMap` 无淘汰 | 改为有界 LRU（生产仍建议落库） | 长跑无增长；列为遗留优化（§6.2） |
| BUG-008 | P2 | 任意 id 查询支付状态都返回“支付成功” | 未判断支付单是否存在 | 增加存在性判断与明确状态 | 不存在 id 与已支付可区分（§5 BUG-008） |
| BUG-009 | P2 | 支付成功但开课消息进死信后被永久放弃，学员无课表 | `order_msg` 超过重试上限转死信后无重放通道 | 增加死信重放任务 | 补开课成功、死信标记已消费、二次触发幂等（§5 BUG-009、`verify-lesson-consistency` 34/34） |
| BUG-010 | P3 | 支付回调无验签，任意请求即视为支付成功 | 回调接口直接返回 success | 增加 HMAC 验签，未配置密钥时 fail-closed | 正确签名通过；错误签名/未配置被拒（§5 BUG-010） |
| BUG-011 | P3 | 笔记内容直接 `v-html`，可存储型 XSS | 未做富文本清洗 | 渲染前消毒 | XSS 用例通过（§5 BUG-011） |

## 3. 上线准备阶段缺陷（GL-001~007）

| 编号 | 级别 | 现象 | 根因 | 修复 | 验证 |
|---|---|---|---|---|---|
| GL-001 | P1 | 迁移第 1 步即撞唯一键，整条链中断 | 演示券 UPDATE 非幂等，第二次执行撞 `(user_id, coupon_id)` 唯一键 | 改为“先探测再动作”的条件式写入，并清理重复行 | 迁移连跑 2 次均 9/9（§1 GL-001） |
| GL-002 | P1 | 第二次执行报 `Duplicate column name` 后中断 | 裸 `ALTER TABLE ADD COLUMN` 依赖忽略报错，但批处理遇首个错误即退出 | 改 `INFORMATION_SCHEMA` 判断 + `PREPARE/EXECUTE` 幂等 DDL | 连跑 2 次 `[OK]`，列与索引只建一次（§1 GL-002） |
| GL-003 | P1 | 上架课程出现 4 个空讲义小节（仅全新环境必现） | 同一课程 id 被两套种子占用，且旧种子无讲义；`INSERT IGNORE` 掩盖冲突 | 补齐讲义、删除误插目录、种子改 `ON DUPLICATE KEY UPDATE` | 空讲义 0、空章节名 0、残留 id 0（§1 GL-003） |
| GL-004 | P2 | 课程封面 URL 被静默截断，图片 404 | `cover_url` 为 `VARCHAR(255)`，实际 URL 269~285 字符；`INSERT IGNORE` 截断写入 | 列宽改 512，并补幂等加宽 DDL | 列宽 512；4 条 URL 完整落库（§1 GL-004） |
| GL-005 | P2 | 空库重建后出现 4 条父课程不存在的孤儿目录 | 迁移假设课程 1 已存在，空库上两条 UPDATE 命中 0 行 | 种子补齐课程 1；UPDATE 改 `INSERT ... ON DUPLICATE KEY UPDATE` | 孤儿目录 0、课程 13、目录 78（§1 GL-005） |
| GL-006 | P0 | 容器化后所有跨服务链路静默失效（券状态不同步、支付不开课等） | 6 个服务 16 处写死 `localhost`，容器内指向自身；compose 未覆盖 | 16 处改 `${SVC_*_URI:默认值}`；compose 注入 15 个变量 | compose config exit 0；A/B 实例对照结果相反，证明覆盖生效（§1 GL-006） |
| GL-007 | P0 | 任何镜像都构建不出来 | `Dockerfile` 的 `ADD target/<模块>.jar` 指向仓库根，而模块 jar 在各模块目录 | 改为 `ADD <模块>/target/<模块>.jar`，新增 `.dockerignore` | 实跑 `docker build` exit 0；镜像内 jar 151 862 354 字节（§1 GL-007） |

## 4. 上线前复测运行期缺陷（B-001~005）

| 编号 | 级别 | 现象 | 根因 | 修复 | 验证 |
|---|---|---|---|---|---|
| B-001 | P0 | 登录用户打开课程列表必现 500，匿名反而正常 | 三元表达式 `int : Integer` 触发自动拆箱，`status=null` 时 NPE | 改显式 if/else，保留 null 语义 | 三种身份不带 `status` 均 200 且返回 13 门；匿名仅上架（§1.1 B-001） |
| B-002 | P2 | 缺必填项返回 500“系统繁忙” | 新增接口无前置校验，数据库非空约束异常被兜底成 500 | 前置判空 + `DataIntegrityViolationException` → 400 | 缺字段返回 400 且含字段名（§1.1 B-002） |
| B-003 | P1 | 发送短信接口必崩 | `@Async` 标注在返回 `R` 的方法上，Spring 代理阶段即抛异常 | 去掉 `@Async` | 接口正常返回，`/sms/**` 无 5xx（§1.1 B-003） |
| B-004 | P1 | 订单 CSV 导出必崩 | 全局响应包装器把二进制 body 强转成 `R` | 方法加 `@NoWrapper` | HTTP 200 + `text/csv` + 可解析正文（§1.1 B-004） |
| B-005 | P2 | 非 multipart 请求打上传接口返回 500 | `MultipartException` 未专项处理 | 增加异常 handler → 400 | 返回 400 且提示格式有误（§1.1 B-005） |
